# Changelog

## Unreleased

**Highlights.** The panel (`sunrice/admin`) and the CMS (`sunrice/cms`) are rebuilt as two packages: a panel framework for any Laravel app, and the CMS as a plugin that uses only the panel's public (`@api`) API. The panel brings sign-in with two-factor login, users and roles with strict rank, resources, React pages through `@sunrice/admin-sdk`, settings, branding, a dashboard with widgets, a media library, an activity log with security events and email alerts, edit locks, AI access over MCP, and Help pages with the developer docs and a user guide in English and Indonesian. The CMS brings collections and entries with drafts, scheduling, revisions and per-entry blueprints, blueprints and fieldsets, taxonomies with term pages, globals, menus, forms, comments, multilingual content with outdated-translation badges and machine translation, and the site side: URLs, templates and components, SEO and structured data, sitemaps, redirects, search and caching. See `docs/README.md`.

### Breaking changes

Each is explained, with what to do, in [`docs/upgrading.md`](docs/upgrading.md#from-the-previous-development-snapshot).

- `route('sunrice.admin.cms.entries.edit')` and `…terms.edit` need the collection's or taxonomy's handle as well.
- A plugin's resources are under the plugin's id (`/admin/shop/products`, `/admin/cms/collections`).
- PHP 8.4 or newer is required.
- `SDK_VERSION` is 3: rebuild plugin bundles with the matching `@sunrice/admin-sdk`.
- Role rank is strict: users and roles one manages must be strictly below them.
- `SecurityAlerts::PRIVILEGED_PERMISSIONS` is gone: use `$panel->privilegedPermissions()`.
- Exports need their own permission (`<prefix>.export`, `cms.entries.export`, `cms.submissions.export`).
- `docs`, `guide` and `resources` are reserved resource keys.
- Run `php artisan view:clear` after updating: `<x-sunrice-cms::form>` is a class component.
- `ForceDeleteEntry` and `DeleteTerm` refuse a referenced entry or term unless `force`.
- The site's words are `sunrice-cms::site.*` translation keys, no longer JSON strings.
- Shared fields inside translated groups, repeater rows and flexible blocks are shared row by row.
- Untranslated pages show the main language (`sunrice-cms.site.fallback`, on by default).
- Hydrated `link` fields and menu links have two new keys each.
- `Globals::get()` reads the current language when none is given.
- `TermsField::toAdmin()` sends `taxonomy` instead of the `terms` options.
- `SiteCache` keeps a content version per area (`remember()`, `key()`, `version()` and `changed()` take areas).
- Page titles end with the site name unless turned off in Settings → Site.
- The page cache never keeps pages with `?q=` or `?reply_to=`; `PageCacheHasher::QUERY` is `['page']`.
- Listing and term pages' `$entries` is a lazy `LengthAwarePaginator` contract, and a term page's includes the terms under it in a hierarchy.
- The comment unsubscribe page asks first and is `sunrice-cms::comment-unsubscribe` (or the site's `cms.comment-unsubscribe`).
- The `sunrice-forms` and `sunrice-comments` rate limiters are gone: form and comment send limits count only what was kept.
- The page cache keeps a page under a `cache.query` parameter only when the page read it (`PageCache::read()`; the entry filter and paginators do), and an entry filter's range, date range, search or option-less select values aren't kept; a site page's `?page=` past a paginator's last page is a 404.
- Forms send visitors back to `#form-{handle}-errors` or `#form-{handle}-status` (was `#form-{handle}`), the replaced thank-you message's id is `form-{handle}-status`, and a slot's markup gets the error summary unless it has its own.

### All changes

- The help under a template setting is short: one line for editors ("Leave empty to use the collection's template.") and a **Which file?** disclosure listing the files tried in order, relative to `resources/views` and wrapping only after slashes, marking the one in use (the entry and term editors get a new `templates` prop: each view and whether it exists, `TemplateHelp::lookup()`). The collection and taxonomy forms' help uses the same short paths. (extra: template help)
- A rejected save shows one error toast: the same messages update the toast already shown (`lib/error-toast.ts`). The entry editor showed two, because its deferred revisions, loaded right after the redirect, came back with the same errors and Inertia fires its error event for each response that has them. (extra: duplicate error toast)
- Content → Translations lists a menu's links as the menu shows them, each followed by those under it, and describes them with their place and filters ("Properties › Link to Properties · listing_type=for-sale"), where filtered links all read "Link to Properties" in database order. (NEW2-i18n-3)
- A listing link with filters ("For sale") and no label in a language shows the main language's label, not the listing's title in that language, which made "For sale" and "For rent" both read "Properti" like their parent; the menu editor's placeholder says so ("as English"). (NEW2-i18n-2)
- A date field set to *Today or later only* refuses an earlier day with its own line, `sunrice-cms::site.forms.today_or_later` ("The Preferred date must be today or a later date.", "… harus berupa tanggal hari ini atau setelahnya."), instead of Laravel's `after_or_equal:today`, whose Indonesian line ended in the English "today". (NEW2-i18n-1)
- The stale-assets warning is part of the page: it sits above the shell and the sidebar and sticky header start below it (on phones it scrolls away with the page), where the fixed sidebar covered its start. It names plugins by their display name (new `PluginBundle::named()`; the CMS's is "Sunrice CMS") and reads "The admin assets of Sunrice and Sunrice CMS are older than the installed packages… run `php artisan sunrice:assets` and `php artisan vendor:publish --tag=laravel-assets --force`.", with the commands as code. (NEW2-front-3, stale-assets banner)
- A form's file field names itself when it refuses a file that could run as code, with the types it takes: "Photos: files of this type can't be sent (accepted: JPG, JPEG, PNG, WEBP)." (`sunrice-cms::site.forms.blocked_type`, `blocked_type_accepted`, in English and Indonesian), like the size messages. (NEW2-front-3)
- Building a menu with a cold site cache costs the same queries however many entry links it has: each link's translation gets its already loaded entry (with its collection), so its address no longer loads both again (2 queries per entry link, 18 on the example's pages). (NEW2-front-2)
- A listing or term page past its last page is a plain not-found page in its head too: `noindex`, no canonical, `hreflang` or `og:url`, and only the site's WebSite and publisher nodes in its structured data (it kept the listing's canonical, alternates and `CollectionPage` for the missing page). `Seo::forPage()` and `StructuredData::graph()` put an error page first. (NEW2-front-1)
- The blueprint builder ties a setting's message to it after a refused save: a group of choices (like an Entries field's "From collections") is marked invalid and described by the message under it, and its checkboxes are marked invalid, so the message is announced and found by tools, not only seen. The message itself already showed under the setting (`fields.0.config.collections` maps to the setting), with the toast. (STR-6)
- `FileContent::containsPhp()` judges the code after `<?=` (or `<? `) with PHP's tokenizer instead of looking for a run of plain ASCII: it counts when, up to `?>` (at most 64 KB), there's no character that code can't hold outside its comments and strings. An image with `<?= … ?>` appended is refused even with non-ASCII bytes in the code's comments or strings, and the bytes `<?=` in a photo's compressed data still don't count. (NEW2-security-1)
- Stale admin assets are hard to miss: when the published panel assets differ from the package's build, or a plugin bundle's published files from its build (new `PluginBundle::publishedFrom($source, $published)`, which the CMS uses), super admins see a warning at the top of each page they load saying what to run. The installation docs explain why symlinked path packages skip composer's scripts, and the real-estate example runs `sunrice:assets` after `composer update`. (NEW-editor-2)
- The page cache no longer floods with copies of a page: a `?page=` past the last page of any paginator on a site page (an entry filter, `Cms::entries()->paginate()`, your own) is a 404, as it was for listings' own `$entries`; past the last of another page name the page is shown but not kept. A `cache.query` parameter counts only on pages that read it with a value they offer (new `PageCache::read($name)`, called by the entry filter for its terms, options and sorts and by paginators for their page name), so `/about?sort=zzz` and `/about?bedrooms_min=5` aren't kept, and a range filter's numbers are kept only when they're among its new `options` (steps; the CMS's markup shows them as selects). An empty parameter keys as the page without it. (CACHE-5)
- Settings sections record the files their media pickers hold on every save, changed or not (they did only when something changed), and a backfill migration records those of every section saved before (`RecordSettingsMedia`), so an existing site's logo is no longer "unused" until its section changes. (extra: branding/settings media)
- `<x-sunrice-cms::terms>` sets each term's taxonomy and its translations' term, so linking the terms (`$term->url()`) costs no query per term (it cost two). (NEW-frontend-4)
- The submission email lists each of several files sent with a field on its own line, with its size and its download link in the admin (it showed only the names). (FORM-6)
